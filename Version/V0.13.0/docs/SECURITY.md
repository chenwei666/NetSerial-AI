# V0.13.0 安全设计 · 正式版源码

## 当前自动任务安全规则

本版已获正式发布授权；生产包沿用原签名，实际构建与升级证据见 TEST_REPORT.md，GitHub 最终状态见根版本历史。以下 V0.12.0/更早内容保留为基础与历史背景；其 AI 草稿规则适用于普通聊天，新增显式任务页面采用本节约束。安全机制的存在不等于已在所有模型、OEM 或交换机验证。

- 用户从当前终端进入任务并点击开始，授权仅限这次目标和连接；无“自动选择最近设备”。不导出任务 Activity。连接令牌、lease、连接代次及设备档案变化检查防止跨设备/过期任务继续执行。
- 查询和有限常规 R2 命令只有通过严格完整命令匹配、设备识别、必要现状读取及目标范围规则才自动执行。高风险/未知分类一律暂停并输入完整目标名称确认，受保护设备还需有效的匹配变更任务/维护窗口。原 R3/R4 风险不得被模型降级；shell、脚本、命令串联、控制字符、未支持解释器和模型内联凭据不放行。
- 单动作严格 JSON，32 步/10 分钟上限；动作、输出和对话有长度界限。设备输出、过去模型消息、记忆都是不可信数据，不构成系统命令或执行授权。任务原始目标与澄清不能因聊天窗口裁剪而失去。
- 停止先同步标记取消，再异步断开/释放资源；离页停止。已进入传输的命令不可撤回。报错、分页/交互、超时、断线、目标改变停止；不自动填确认提示、重试、恢复、保存或回退。
- 只向当前选定 provider/model 发起请求，无自动服务商切换。已启用的确认记忆最多召回 5 条，沿用聊天偏好；自动任务不自动保存记忆。保留自由文本脱敏限制，用户不得把密码放在目标或普通追问里。

### 本地 Web 密码路径

WEB_ACCESS JSON 只能包含动作类型、解释、用户名和 HTTP/HTTPS boolean，不得包含密码或任意命令。仅使用本地支持的 H3C Comware 5/7、Huawei VRP、Cisco IOS/IOS XE、Ruijie RGOS 模板；主版本/语法证据不足不代表兼容。创建/覆盖用户、管理权限及 HTTP 暴露均在整份本地模板的高风险确认中提示。

专用输入界面使用安全窗口、密码遮罩，禁用保存/自动填充/内容捕获/复制；口令以 `char[]` 交付执行器，不进入 AI、聊天或长期记忆，取消/超时/提交清理输入与未交付数组。允许 8–64 位可打印 ASCII，至少字母与数字，排除不安全 CLI 字符。提交口令不等于批准配置，之后仍单独确认模板。建议可信输入法与 HTTPS；这些 UI 保护不能防止恶意输入法、Root 或被攻陷的系统。

发送敏感命令前在原始传输入口开启回显抑制，防止分块/延迟口令回显进入终端、AI 或证据。抑制持续至重新连接；流程不再把秘密阶段输出发给模型。提示符返回不证明配置效果、网页可达或账号登录，必须重新连接进行现场验证。不自动回退或保存。

**内存边界：** 可变口令数组会清零，但现有本地模板/传输会产生不可变 JVM String，Android/IME 也可能有副本；不宣称可靠擦除进程内全部秘密。本版仍需真实模型、不同 Android/OEM、USB/SSH/Telnet 及实际交换机验证。

## V0.12.0 免 Root 工具箱

- 默认只运行用户选中的工具，不因打开页面、搜索或切换工具触发探测。当前任务有取消、时间和输出边界；取消同时中断工作并关闭注册的 Socket/进程，旧任务回调不得覆盖新任务结果。系统 DNS 的不可中断底层调用通过复用有限线程池限制资源增长。
- `ACCESS_NETWORK_STATE` 是读取默认网络、接口、路由和 DNS 所需的普通权限，不增加 Root、定位、VPN 抓包或受保护 Wi-Fi 标识读取。当前网络页面需 Android 6.0+；结果只代表默认网络，接口 MTU 不是路径 MTU。
- Ping/TTL/IPv4 DF 使用参数化系统命令，不拼接 shell。权限失败、系统不支持、无回包和真实测量分开；无回包不记作 0 ms。路由追踪的未知跳不代表链路中断，DF 超时不作为路径 MTU 上界，1500 字节成功仅作为已证实下界。
- 单目标 TCP 仍为最多 16 个明确端口。新增发现功能与其分开，运行前明确确认：仅 RFC1918 私网 `/26`–`/32`、最多 64 个地址与 4 个 TCP 端口、40 秒预算。只用于用户拥有或获授权网络；不允许公网网段、自动扩大范围、后台周期扫描。未响应不能证明离线；拒绝可能由中间防火墙产生，不是完整资产发现。
- WOL 运行前确认目标和 MAC，拒绝无效或组播 MAC，只向明确 IPv4 单播/广播地址 UDP 9 发送一次 102 字节魔术报文。“已发送”不代表目标收到或已开机，不附带远程账号口令。
- DNS 默认从 Android 当前网络读取服务器；用户可显式填写 `TYPE @服务器IP`。无系统 DNS 地址时仅 A/AAAA 可用系统解析器，不自动改为公共 DNS。显式查询校验事务 ID、来源、回显问题、帧与记录长度和压缩指针；UDP 截断后只重试同服务器 TCP。TXT、别名等只是有界文本，不触发额外连接或脚本；不验证 DNSSEC。
- HTTP 只向明确 URL 发一次 HEAD，不发送账号、Cookie 或 Authorization，不跟随跳转、不读取正文。响应头上限 32 KiB；报告只保留有限白名单字段，隐藏 Cookie、URL 路径/查询及不安全跳转内容。拒绝 URL 内嵌凭据，HTTPS 不降级。用户明确选择的 HTTP 是明文诊断 Socket；应用全局 `usesCleartextTraffic=false` 保持不变，并非授权其他模块改为明文。
- TLS/HTTPS 使用正常系统信任链；API 24+ 在握手中做 HTTPS endpoint identification，API 21–23 使用平台 HTTPS hostname verifier 完成强制域名校验。没有 all-trust、忽略证书或绕过身份校验开关；证书失败不会作为成功导出。不声称已检查吊销状态或穷举服务端全部 TLS 协议。
- 报告使用既有脱敏器并先显示预览，用户再明确复制、分享或带入 AI 草稿；进入草稿不提交 AI，仍需手动发送。地址、设备名、DNS TXT 或服务端文本仍可能包含未被识别的业务信息，人工复核不可省略。工具结果不执行命令或改变交换机配置。
- V0.11.0 确认式记忆和既有终端安全门禁保持。独立 `.preview012` 不覆盖或自动读取正式版/旧预览数据；正式 `com.chenwei666.netserial` 沿用原签名覆盖升级，不改变凭据格式。旧自动记忆不会自动导入确认记忆，真实用户数据迁移未在测试中读取或验证。

English boundary: explicit, bounded, cancellable probes only; no Root or hidden public DNS. Private discovery and WOL require confirmation. HTTP is credential-free HEAD without redirects; TLS keeps trust and hostname checks. Reports are previewed before manual sharing/AI submission. Device/OEM restrictions and unknown measurements remain visible rather than being presented as success.

## V0.11.0 确认后记住

- 长期记忆与聊天历史分开：聊天历史按既有规则自动加密保存；长期记忆必须由用户选择“记住”或“添加记忆”，核对并编辑内容、选择适用范围，最后点击“确认保存”。浏览对话、接收回复和调用记忆管理都不会自动提取或保存长期记忆。
- 个人偏好适用于所有设备；设备记忆只按当前**设备档案名称**精确匹配。这不是经过验证的硬件身份，重名档案会共享同名设备记忆，改名后不会自动迁移；请为不同设备使用唯一档案名称。`Default switch` 和新手排障入口不启用设备范围，只可使用个人偏好。
- `ConfirmedMemoryStore` 使用独立 schema 与用途标识，`EncryptedConfirmedMemoryPersistence` 通过既有 `CredentialVaultFactory` 保存 AES-GCM 密文。存储记录 alias 为 `confirmed-chat-memory-v1`，同时作为 AAD 与其他用途隔离；底层复用既有 Android Keystore 密钥，不宣称独立生成一把硬件密钥。
- 不读取、导入或自动信任旧版自动记忆。旧 `MemoryVault` 和设备档案页面保留兼容，但不会作为新 AI 聊天长期记忆的后备来源。Android 6.0 以下禁用加密长期记忆，不降级为明文。
- 最多 100 条、每条最多 1024 字符、总内容最多 32768 字符；确认保存或编辑后有效期为 180 天。过期条目不再显示和召回，可在后续成功写入时清理；读取本身不修改存储。超长输入明确报错，不静默截断。
- 开启“使用记忆”后，每次主动发送最多附带最近确认的 5 条适用记录，并显示本次选用记录的不可变快照；后续编辑或删除不会修改该快照，也不能撤回已发送到服务商的内容。请求仍经过既有脱敏与提示注入清理，因此条目被选用不表示其所有原文都会发送。
- 编辑采用单次替换写入，删除需再次确认；同进程多个存储实例使用统一锁保护读取—修改—写入。损坏、未知 schema、解密失败或容量异常会失败关闭，不能通过空列表回退覆盖原有坏数据；读取失败时阻止启用记忆的当前请求，不静默调用旧记忆。
- 保存前拒绝可识别的密码、API Key、Token、私钥和常见设备凭据。规则不是对所有自由文本秘密的证明：用户仍需人工检查，避免保存账号口令、内部业务敏感信息或不应提交服务商的内容。记忆管理窗口使用 `FLAG_SECURE`，编辑框禁止状态保存和自动填充。
- 保存、编辑、删除和本地召回记忆不调用 AI 服务，也不产生付费 AI 请求。用户主动点击发送后，所选服务商会收到启用的相关上下文，可能按其 API 计费；关闭记忆只影响长期记忆附带，不等于删除聊天历史或关闭其它已选择的上下文。

下列版本章节保留历史设计背景；涉及 AI 聊天长期记忆的旧行为，以本节 V0.11.0 规则为准。

## V0.10.0 新手向导边界

- 网络向导仅检查用户填写的一个目标、三次 Ping 和一个指定 TCP 端口；有超时、取消和并发边界，不扩展为子网扫描。不把 Ping 失败当作离线，也不把 TCP 成功当作认证成功。
- 交换机向导只给出只读命令草稿与离线解释，未知品牌不猜测厂商命令；接口和 VLAN 参数拒绝换行、控制字符及命令注入。用户需在终端核对目标并手动执行，原有 R0–R4 门禁不变。
- 继续排障仅保留当前进程内的有界脱敏草稿；回显在截断前先脱敏并优先保留最新内容。显式结束或退出进程后草稿消失。
- 分享前显示完整报告预览；导向 AI 时创建新草稿，不自动请求上游服务，也不附带错误的默认 H3C 设备上下文。
- 本地脱敏不能保证移除全部内部地址、设备名称与业务内容；分享、提交 Issue 或发送 AI 前仍需人工复核。保存的配置快照可能缺页或截断，不是完整恢复备份的保证。
- 独立 Debug 包不自动读取或迁移正式版 API Key、连接和对话历史；正式版继续沿用仓库外既有生产证书，不引入新的凭据存储方式。

## V0.9.1 当前会话读取边界

- 只读取已连接终端已经接收/显示的文本，不主动探测网络、不打开第二连接、不自动发送命令。
- 写入共享快照前清理 ANSI 控制序列并执行敏感字段脱敏；密码专用发送路径只记录脱敏占位符。
- 仅保留最多 4 个会话、每会话最近 100,000 字符；不落盘，应用进程退出即消失。
- 断开连接后会话立即失去可读资格，清屏同步清除对应快照。
- Store 不暴露连接对象或命令执行回调，运维中心生成的命令仍进入既有人工确认与 R0–R4 门禁。

## V0.9.0 新增控制

- 对话最多保存 12 个会话、每个 50 条消息、单条 24,000 字符、单会话 120,000 字符、总序列化内容 400,000 字符；越界或损坏历史失败关闭。
- Android 6.0+ 对话历史使用 Android Keystore AES-GCM 和固定用途 AAD 加密；Android 5.x 不降级为明文持久化，凭据库以 fail-closed 方式拒绝密钥操作，仅无凭据 HTTPS Ollama 可对话。
- 发送前清理 ANSI、凭据赋值、Bearer、私钥、常见本地用户和 SNMP community；终端/记忆中的提示注入特征行会被删除。
- 模型回复再次执行 ANSI 清理和敏感字段脱敏；只有显式围栏且符合网络 CLI 前缀白名单的行才可成为装载候选。
- AI 命令必须通过确定性 R0–R4 规则；R4 始终阻断，R1–R3 仍需用户确认且最终继续经过终端目标与变更门禁。
- 取消请求会断开活动 HTTPS 连接且不会触发厂商故障转移；页面销毁会取消请求并停止执行器。
- 一键故障取证只生成有上限的只读命令；运行手册默认 20 秒超时、一次重试、首错即停，不在规划页面直接连接设备。
- 变更启动要求四阶段计划，完成要求 `COMMAND_SENT` 与输出/验证证据，避免只有工单标题而无闭环证据。

## V0.8.0 新增控制

- 模型目录请求只接受绝对 HTTPS 地址、禁止重定向，并复用 AI 请求的连接/读取超时和 1 MiB 响应上限。
- Bearer、Anthropic x-api-key 与无凭据 Ollama 三种认证模式显式隔离；凭据必须是可见 ASCII，防止请求头注入。
- 模型缓存只保存模型标识和时间戳，不保存 API Key、授权头或响应原文；用户可随时清除。
- 上游失败不会阻塞手工模型输入；错误信息按认证、限流、TLS、超时和网络类别展示，不回显服务端敏感响应。
- TCP 批量检查限定为用户明确输入的单个目标和最多 16 个端口；范围必须递增，单端口连接超时最多 1.5 秒，不支持网段扫描。
- 网络诊断同时只运行一项，目标仍经格式校验并作为独立 ProcessBuilder/Socket 参数使用，不拼接 shell。

## V0.7.0 新增控制

- 高级工具窗口设置 `FLAG_SECURE`；凭据禁止 Autofill/状态保存，保存后清空字符数组与输入框，只能检查存在性、不能回显。
- HTTP 使用 128 位随机路径令牌、GET-only、`no-store`/`nosniff`；TFTP 只支持 RRQ/octet、随机文件名和 31 MiB 上限。两者只绑定私有/回环地址。
- 运行手册限制 1 MB、500 条命令、单条 512 字符，必须通过 RSA/SHA-256 公钥签名，并拒绝 credential-like 命令。
- SNMPv3 限制为不超过 256 地址的 IPv4 CIDR 和允许列表算法，不持久化认证密钥。
- AI 失败转移不传播原始网络异常；受控批次限制 25 个唯一目标、拒绝内联凭据并要求四阶段与逐目标审批。

## V0.6.0 新增控制

- Web 管理员密码只在当前向导和发送动作中存在；预览、终端显示、证据和回退文本均使用脱敏占位符。默认仅启用 HTTPS，HTTP 需要显式勾选并确认风险。
- GitHub 更新检测禁止重定向、限制响应大小和超时，只解析 Latest Release，并只接受 GitHub 域名的 HTTPS Release/APK 地址；应用不会自动安装 APK。
- AI 诊断只接收有长度上限、已清洗 ANSI、已脱敏的终端上下文；记忆继续要求用户显式勾选，并执行既有保留期与敏感内容拒绝规则。
- 多会话档案只包含名称、协议、主机、端口和用户名；密码、私钥与跳板凭据不保存。
- 配置快照写入前脱敏并规范化，且设置数量与总容量上限。
- 自定义命令拒绝控制字符、多行、重复项以及被敏感信息脱敏器改写的内容，并保守标记为配置风险。
- XMODEM 限制为 16 MiB，发送前展示 SHA-256，协商、等待和重试均有上限，传输开始前再次校验 R3 目标授权。
- 设备识别与合规检查属于启发式辅助，不构成身份认证、授权或合规证明。

## 既有安全设计

## 风险模型

主要风险包括：连错设备、维护窗口外变更、多行粘贴绕过、AI 幻觉或提示注入、凭据进入日志/导出、SSH 主机冒充、Telnet 明文、SFTP 误上传和诊断输入被当作系统命令。

## 控制措施

- **目标确认**：终端常驻显示设备名、地址、环境、厂商和保护状态，并按目标稳定着色。
- **变更授权**：受保护设备上的 R3/R4 操作必须存在设备名匹配且位于维护窗口内的活动任务。
- **逐行分级**：粘贴或批量命令逐行检查，以最高风险决定门禁，避免低风险首行掩盖后续危险命令。
- **R4 限制**：AI 路径拒绝 R4；人工终端路径保留强提醒和显式确认。
- **AI 不可信**：终端上下文先脱敏并删除提示注入特征行；模型输出再次解析、分阶段校验和本地风险复核。
- **凭据保护**：AI Key 使用 Android Keystore 支持的加密存储；SSH/Telnet/跳板口令及私钥不持久化。
- **主机密钥**：SSH 使用 `known_hosts`、HashKnownHosts 和 StrictHostKeyChecking；已知密钥变化时拒绝连接。
- **SFTP**：仅在已连接 SSH 会话启用；上传按 R3 处理，受保护目标需任务和二次确认。
- **导出脱敏**：覆盖 API Key、Token、Bearer、密码、私钥，以及常见 username secret、enable secret、SNMP community 和本地用户密码语法。
- **网络探测**：主机、端口和超时均校验；系统工具使用参数列表启动，不使用 shell；输出和执行时间受限。
- **屏幕保护**：远程终端、AI、设备档案、变更任务等敏感页面使用 Android 安全窗口标志，阻止常规截图/录屏。

## 数据保留

变更任务最多保留 20 条，证据在写入前脱敏并保存在应用私有区域。用户可通过应用数据清理删除。Markdown/PDF 由用户选择保存位置，导出后由用户负责文件访问权限和保留周期。

## 已知边界

- Telnet 没有加密，无法防止同网段监听或篡改。
- Android Keystore 保护取决于设备锁屏、系统完整性和厂商实现；Root 设备不视为可信环境。
- 正则脱敏无法证明覆盖全部厂商私有语法，导出前仍须人工复核。
- 主机密钥首次信任依赖工程师通过可信渠道核对指纹。
- 路径 MTU 和 ICMP 探测可能被 ACL、系统能力或中间设备策略影响。
- AI 服务商会收到用户选择发送且已本地清理的上下文；敏感环境应使用批准的服务商或本地模型。

## 发布检查

发布前必须执行单元测试、Lint、Release 构建、ZIP 对齐、APK 签名验证、证书指纹核对、SHA-256 生成和发布内容敏感信息扫描。
