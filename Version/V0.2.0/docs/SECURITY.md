# V0.2.0 安全说明

## 已实施

- Android 自动备份关闭。
- 明文 HTTP 默认关闭。
- 仓库忽略 `.env`、密钥库、本地 SDK、构建缓存和 APK/AAB。
- AI 供应商草案必须通过本地 `ExecutionGuard`。
- AI 风险等级不能降低确定性规则给出的风险。
- R4 命令需要强确认且永不允许自动执行。
- API Key、Token、密码、私钥和 SNMP 团体字不属于 AI 记忆数据。
- AI API Key 使用 Android Keystore 管理的 AES-GCM 密钥加密；应用偏好中仅保存版本号、随机 IV 和密文。
- `ProviderProfile` 仅保存凭据别名；明文凭据仅在 `CredentialVault` 受控回调期间存在，回调结束后字符和字节缓冲区均清零。
- 多厂商凭据按别名隔离；别名经过标准化、哈希为持久化键名，并作为 AES-GCM 附加认证数据阻止密文跨别名替换。
- Android 6.0 以下设备不启用 AI 凭据存储，且不允许不安全降级。
- AI HTTP 仅允许 HTTPS，禁止自动跟随重定向，避免向其他地址转发 Authorization。
- Endpoint 拒绝用户信息、查询参数和片段；鉴权值拒绝空白与控制字符，防止请求头注入。
- 终端上下文在发送前按敏感关键字整行遮蔽，并限制长度。
- 成功响应限制为 512 KiB；非成功响应正文直接丢弃，异常对象只保留安全分类和状态码。
- AI 设置 Activity 使用 `FLAG_SECURE` 阻止截图和最近任务预览；API Key 输入关闭自动填充和实例状态保存，页面进入后台时立即清空未保存输入。
- Profile JSON 只保存厂商、HTTPS 地址、模型和随机凭据别名，最多 32 项；密钥明文不参与 JSON 编解码。
- 连接测试必须由用户显式确认，可能产生费用的提示会在请求前展示；测试请求使用空终端上下文，并支持生命周期取消。
- 已保存密钥的 Profile 更换厂商或 Endpoint 时必须输入新密钥，并使用新随机别名替换；旧密钥绝不会复用于新目的地址。

## 后续接入真实 AI 前的门禁

1. 企业部署优先使用 AI Gateway 短期令牌，供应商长期密钥只在服务器保存。
2. 专用供应商适配器必须复用 HTTPS、请求超时、响应大小、取消和安全错误分类；模型能力和费用预算仍需后续实现。
3. 发送前展示并脱敏终端上下文；设备输出和知识库内容都按不可信输入处理。
4. 崩溃日志、备份、测试夹具和导出文件必须通过敏感信息扫描。
5. 在真实 Android 设备上验证 Keystore 创建、覆盖、读取、删除、系统升级和应用数据清除行为。

V0.2.0 已完成通用兼容 HTTP 路径和 App 内设置界面，但开发、构建和测试过程没有配置或调用任何真实 AI 密钥；物理设备和真实厂商验收仍未完成。
